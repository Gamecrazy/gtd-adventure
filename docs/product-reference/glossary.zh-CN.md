# 术语表

本公开原型采用的 GTD 中文规范词参考。冒险称谓是体验包装，不能改变这些词的底层语义。

本仓库的游戏化称谓仍是设计候选，规范词用于明确对应的 GTD 概念。

## 五步

| 规范词 | 不要用 | 它是什么 |
| --- | --- | --- |
| 收集 | 捕捉 | 把引起注意的事务从脑子里拿出来，归拢到系统里。 |
| 理清 | 明确、处理 | 看清每一项是什么、要不要行动，并决定去向。 |
| 组织 | 组织整理 | 把理清后的结果放进对应清单和资料。 |
| 回顾 | 检查、深思 | 按合适的频率查看系统，保证它仍可信。 |
| 执行 | 做 | 按情境、时间、精力和重要性选择当下最合适的行动。 |

「明确」只保留普通汉语用法，例如明确确认、明确记录；不再作为第二步的阶段名。

## 清单

| 规范词 | 不要用 | 它是什么 |
| --- | --- | --- |
| 工作篮 | 收件箱 | 尚未理清的收集入口，对应书中的工作篮。 |
| 下一步行动 | — | 下一步要做、且现在就能做的具体行动。 |
| 日程表 | 日历 | 必须在特定日期或时间发生的行动与信息。 |
| 等待 | — | 已交给他人、自己在等结果的事项。 |
| 将来/也许 | 将来也许 | 现在不承诺、以后再考虑的孵化器。 |
| 参考资料 | 资料 | 没有下一步行动、但可能要查阅的材料。 |
| 备忘录 | 未来提醒、Tickler | 未到期前从底层清单隐藏、到期后再出现的提醒。 |
| 垃圾 | 废纸篓 | 没有价值、已丢弃的事项。 |
| 已完成 | — | 已经做完、只供查阅的事项。 |

备注仍称「备注」，不要和备忘录混用。事项在界面称「事项」「内容」或「待理清事项」，不显示 Stuff 等技术类型名。

## 分类、视角与规划

| 规范词 | 不要用 | 它是什么 |
| --- | --- | --- |
| 情境 | 标签 | 执行时的地点、工具或状况；产品里用 Tag 实体，输入仍写 `#名称`。没有单独的 Context 实体。 |
| 核查清单 | 检查表 | 可重复使用的步骤清单，避免漏做。 |
| 核查项 | 检查项 | 核查清单里的一条。 |
| 目的 | 使命 | 长期方向：为什么做这些事。 |
| 原则 | — | 做决定时要守住的标准；写在目的下面。 |
| 愿景 | — | 较长周期里希望看见的生活和工作状态。 |
| 目标 | — | 有时限的阶段性成果。 |
| 关注领域 | — | 需要持续维护的责任范围，不是一次性项目。 |
| 项目 | — | 需要多个步骤才能完成的预期成果。 |
| 自然计划法 | 自然式项目规划、自然式规划 | 目的与原则、预期成果、头脑风暴、组织、下一步行动。 |
| 清空大脑 | 思维清扫 | 用触发清单把脑子里还没写下的事倒进工作篮。 |
| 未尽事宜触发清单 | 未尽事宜触发项、未尽事宜触发词 | 帮助想起未尽之事的提示列表。 |
| 每周回顾 | — | 定期清空大脑、校准清单并为接下来确定方向。 |
| 视角 | — | 从目的到行动的高度检查，不是又一套清单。 |

## 书里没有、产品保留

例程、看板、人员、分析、聚焦。人员不称「协作者」。

## 文案规则

- 项目名称提示使用「写成已经实现的成果」，不复制 FacileThings 英文示例。
- 领域错误代码不直接暴露，统一映射为简短中文和可执行下一步。
- 游戏化称谓必须能映射回本表中的规范词；不新增平行 GTD 概念。

# 原型响应式与可访问性边界

本文只约束本公开原型的界面，不包含生产应用的路由或部署信息。

## Editors fit the viewport

在 **1024×750** 及以上桌面视口，用户应能看完固定决策字段并使用主要操作，不需要滚动整张表单。

- 固定字段采用标签在左、控件在右的紧凑布局。
- 为输入框保留实际可用宽度，不把中文标签挤成竖排。
- 保存、取消、确认、完成等主要操作留在首屏，必要时使用底部固定操作区。
- 备注、事项列表等用户控制长度的内容可以在自身区域滚动。
- 不用没有信息的留白扩大决策页面。
- 长文本、错误提示和空状态也应有明确操作路径。

## 窄屏

- 保留顶部五步入口，不把导航隐藏成不可到达的功能。
- 主要内容改为单列，执行页通过可操作的面板切换保留任务优先级。
- 触摸操作目标至少 44px。
- 页面不应出现非预期的横向溢出。
- 避免底部导航遮挡操作，并考虑设备安全区域。

## 键盘与反馈

- 控件提供清楚的名称及可见焦点。
- 页签正确报告当前状态，支持方向键、Home 和 End。
- 对话框提供名称、关闭方式和合理的焦点恢复。
- 颜色不是状态的唯一表达；完成、错误、等待等同时提供文字。
- 切换页签不丢弃尚未确认的编辑。
- 尊重减少动态效果的系统偏好。

## 验证边界

DOM 与交互测试可以验证状态和操作路径，不能证明视觉上没有重叠或裁切。发布时仍需在真实浏览器检查桌面、手机及原生对话框；当前原型尚未完成该截图验收。
